# Tabs redesign: History / Cherry-pick
Objective: split history and mass cherry-pick into tabs, branch picker above filters, cherry-pick list with progress and conflict detection.
Branch: feat/cherry-pick-app · Delivery: ask-on-risk · Runners: `cargo test` (src-tauri), `npm test` + `npx tsc --noEmit`.

## Specs
- S1 "Vamos a remover el sidebar izquierda de ramas, ahora se pondrá arriba de los filtros del listado como un selector buscador." Same ordering (main/develop/release first) and search ranking as before.
- S2 "Vamos a dividir las funciones de listado y cherrypick masivo en tab." Tabs: History, Cherry-pick. History stays usable while a cherry-pick runs; the Cherry-pick tab shows progress (e.g. 3/10) and turns red on conflict.
- S3 "los commits seleccionados en la lista debe haber un botón donde cargue en el tab de cherrypickmasivo". After loading: switch to the Cherry-pick tab and clear the History selection. One branch at a time: if the list holds commits from another branch, ask before replacing. Shift+click selects a range A..B in History.
- S4 "El tab de cherrypick masivo mostrara los commits seleccionados en una tabla la cual puede eliminar". Columns hash, subject, author, date, status, remove. Before start any row can be removed; while paused on a conflict, only pending rows after the current one. Target picker (searchable), editable branch name (template) and Start button live in the tab (no dialog). Choosing a target marks commits already in it ("Ya está en destino") with a remove-all action. "Agregar por hash": pasted hashes from any branch are added to the list; unknown, merge and duplicate hashes are reported and dropped.
- S5 "El tab de cherrypick mostrara una barra de progreso en la cual indicara el progreso de la tarea." N/M with counts per status, updated while applying.
- S6 "al detectar conflicto avisara al usuario y también pondrá una opción para que resuelva en vscode". Red banner with the files; a Windows notification when the app is not focused (tauri-plugin-notification). "Resolver en VS Code" opens the worktree folder plus the conflicted files.
- S7 "como dectetar si el usuario resolvió el conflicto para que pueda continuar". Poll the worktree every few seconds; when no conflicted file has markers (or the pick was committed outside the app) show "Resuelto" and enable Continue. The user still clicks Continue.
- S8 Teammate changes: paste hashes (S4) and range A..B (S3).
