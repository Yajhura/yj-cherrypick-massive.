# Selection, existing branches and the Branches tab
Objective: seven improvements to selection, branch naming and filters, plus a side-by-side Branches tab, a txt export of selected commits and a clickable repo folder.
Branch: feat/cherry-pick-app · Delivery: ask-on-risk · Runners: `cargo test` (src-tauri), `npm test` + `npx tsc --noEmit`.

## Specs
- S1 "mejorar el seleccionar como con shitft y control": plain click shows the commit's detail and does not change the selection ("Volver a: click = detalle"); Ctrl+click toggles one commit keeping the rest; Shift+click selects the range from the last toggled row; the row checkbox keeps toggling.
- S2 "debe haber un boton donde te lleve al ver los cambios no dando doble click": an icon button in each row (visible on hover or focus, "Ícono en cada fila") opens the commit in the Code tab; Enter still opens it; "Ver código" in the detail pane stays.
- S3 "el doble click en el commit sera para seleccionar": double click toggles the commit's selection and no longer opens the Code tab.
- S4 "que la rama generada también tenga concatenada la hora y minuto": new placeholder `{time}` (HHmm); the default template becomes `cherry-pick/{target}/{date}-{time}`. Assumption: a template the user already saved is kept as is.
- S5 "Dejar que se use rama ya existente pero siempre avisando en cherrypick masvio" / "Sumar commits encima (Recommended)": when the branch already exists, the commits are applied on top of it and pushed without force; the row warns that it exists and the start asks for confirmation; the same per target in a queue. Assumptions: a branch that exists only on the remote is checked out from the remote branch; aborting or applying nothing never deletes an existing branch, and aborting moves an existing local branch back to where it was.
- S6 "Por defecto que el rango de fecha esten seteado el dia de hoy" / "Desde y hasta = hoy (Recommended)": from and to start at today when a repo opens or the branch changes; clearing them shows everything.
- S7 "agregar un checkbox que desmarque los seleccionados solo aparece cuadno hay commits seleccionados": while commits are selected, a checked checkbox with the count shows in the list header; clicking it clears the selection and it disappears. In History and in each Branches column; Esc also clears.
- S8 "se hara un nuevo tab donde podre seleccionar ramas por ejemplo 2 y ver en cada uno sus commits correspondiente la cual también podre filtrar cada uno" / "Columnas lado a lado (Recommended)" / "De 2 a 4 (Recommended)": a Branches tab with 2 to 4 side-by-side columns, each with its branch picker, its filters (text, author, dates, ticket) and its commit list with the same selection; each column has "Cargar N en Cherry-pick" (replacing the basket from another branch asks first) and "Exportar txt" ("Cargar a Cherry-pick y exportar (Recommended)").
- S9 "porder exportar mis commits seleccionados en un txt que servirá para usar en el cherrypick masivo con el agregar por hash" / "Hash + asunto como comentario (Recommended)" / "Junto a 'Cargar N' y en la tabla (Recommended)": one line per commit, `<full hash>  # subject (author)`, saved with the Windows dialog; button next to "Cargar N" in History and on the Cherry-pick table; "Agregar por hash" ignores everything after `#` on a line.
- S10 "Donde aparece el nombre de la carpeta que sea clickleable la cual me abre el explorador con la ruta de la carpeta": the repo folder name in the toolbar is a button that opens Windows Explorer at the repo root.
